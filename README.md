Native Vulkan renderer for the Caelix voxel engine. The core is a C++20 shared
library (`caelix_renderer`) that exposes a small C ABI (`include/caelix/caelix.h`).
A Rust standalone host (`host-rs/`) links the library through bindgen-generated
bindings. A Unity native plugin that uses the same C ABI comes later.

The library contains NVIDIA Real-Time Denoisers (NRD, compiled in) and, in the default
Windows build, NVIDIA DLSS through the NGX SDK (the static NGX import library compiled
in, the feature DLLs `nvngx_dlss.dll` and `nvngx_dlssd.dll` next to
`caelix_renderer.dll`). Their license obligations (credits line, NVIDIA marks on splash
screen and about box for DLSS, notification before a commercial release, distribution) are
summarized in [`third_party/NOTICES.md`](third_party/NOTICES.md); read it before you ship a
build.

## Architecture

The host owns the Vulkan instance, the device and the swapchain. The library
never creates a device: it publishes what it needs
(`caelix_get_device_requirements`: Vulkan 1.3, extensions, feature bits), the
host creates a device that meets those requirements, and the library adopts it
(`caelix_device_adopt`). The library loads Vulkan through the host's
`vkGetInstanceProcAddr` (volk), so it sees the same layers as the host. Each
frame, the library records its work into a command buffer that the host
provides; the host submits and presents. Vulkan handles cross the C ABI as
`uint64_t`, so the header needs no Vulkan headers.

In `host-rs/`:

- `caelix-sys`: raw bindings to the C ABI.
- `caelix-vk`: instance, device, swapchain and frame loop. It is the only Rust
  crate with Vulkan code (`ash`); its public API exposes raw `u64` handles only.
- `caelix-app`: the window (winit), the CLI and the glue between the two.

### Source layout

The library sources are in `lib/src/`, one namespace `caelix`. Includes are
relative to `lib/src/` (`#include "rhi/device.h"`).

- `abi/`: the C ABI entry points (`caelix.cpp`); they convert exceptions to `CaelixResult`.
- `core/`: logging, the Vulkan include header (volk, VMA) and the hash map alias.
- `rhi/`: thin Vulkan wrappers (device, buffers, images, compute pipelines, GPU timers, staging ring, shader loading).
- `rhi/alloc/`: GPU memory pools (record pages, row ranges, acceleration structure blocks).
- `scene/`: `Scene` (one class in `scene.h`, split into `scene_entities.cpp`, `scene_bricks.cpp`, `scene_flush.cpp`, `scene_accel.cpp`, `scene_materials.cpp`), the CPU mirrors of the GPU tables and the material table (`material_table.*`, built-in glass palette `glass_palette_default.inc`, generated by `tools/gen_glass_palette.py` from `data/glass-palette.json`).
- `render/`: `Renderer` (one class in `renderer.h`, split into `renderer_targets.cpp`, `renderer_render.cpp`, `renderer_denoise.cpp`, `renderer_upscale.cpp`), the frame constants, the NRD executor, the generic `Upscaler` interface (`upscaler.h`) and its DLSS implementation (`dlss_upscaler.*`: `NgxRuntime`, `DlssUpscaler`; CAELIX_DLSS builds only).
  `render_kernels.*`: `RenderKernels`, the per-device objects that every renderer and NRD executor of a device shares (set layouts, compute pipelines, sky sampler, fallback sky cube, NRD pipelines).
- `light/`: the light tree (`docs/LIGHT_TREE.md`): `light_tree.*` (hooks, code set, Prepare, Stage), `light_tree_record.cpp` (transfers, group pass, gather and build recording, readback, stats), `light_tree_layout.h` (GPU layouts, named offsets, push structs). The `Scene` side (options, stats, requeue) is `scene/scene_light.cpp`.

The HLSL is in `shaders/`, the include root of DXC (`#include "common/caelix_platform.hlsl"`):

- `shaders/common/`: the platform header, the record and table layouts, the frame constants and their uniform buffer declaration (`caelix_frame_ubo.hlsl`), the block decode, the material table lookup (`caelix_material.hlsl`).
- `shaders/scene/`: the finalize kernel and the record / neighbour lookups it shares with the light tree (`caelix_scene_lookup.hlsl`).
- `shaders/hash/`: the maintenance kernels of the GPU hash table (`docs/HASH_TABLE.md`; its device API is `common/caelix_hash_table.hlsl`).
- `shaders/light/`: the light tree (`docs/LIGHT_TREE.md`). `caelix_light_tree.hlsl` is the device API (sample, pdf) that the render kernels include; `records/` is the group pass that computes the brick light records (group, size, scan, build, commit); `bvh/` is the BVH build (gather, radix sort, Karras, aggregate, depth, wide, finish). The layouts stay in `common/caelix_light_tree_layout.hlsl`.
- `shaders/render/`: the trace and composite kernels, the brick DDA, the shading helpers.

A kernel's name is its file name without the folder (`caelix_finalize`), so
kernel file names must be unique across the folders (CMake checks it).

### ABI version 2: the scene

`CAELIX_ABI_VERSION` is 2. Version 2 adds the scene API (`caelix_scene_*`):
entities, raw brick upload and removal, a per-frame flush, stats and a brick
query for inspection. The flush runs the finalize kernel and builds the
acceleration structures (see below). The renderer API (`caelix_renderer_*`,
see "Renderer") traces the scene into the host's image. All calls on one scene
(or on a scene, its renderer and its device) are externally synchronized by the
host.

Version 2 is still in development: the finalize step appended fields to
`CaelixSceneDesc` (`encoding`, default 0 = packed), `CaelixSceneStats`
(`finalized_bricks_total`, `reverse_table_bytes`, `aabb_bytes`, `grid_bytes`)
and `CaelixBrickInfo` (`aabb_buffer`, `aabb_row_offset_bytes`) without a
version bump. The acceleration structure step appended
`CaelixSceneDesc::scratch_bytes` (default 0 = 128 MiB), six `CaelixSceneStats`
fields (`blas_count` .. `as_builds_pending`), four `CaelixBrickInfo` fields
(`blas_address`, `blas_handle`, `entity_info_buffer`,
`entity_info_offset_bytes`) and the function `caelix_scene_get_tlas`, also
without a bump. The renderer step removed the temporary `caelix_clear_target`,
added the renderer API and the feature bit
`CAELIX_FEATURE_STORAGE_IMAGE_WRITE_WITHOUT_FORMAT` (bit 9,
`shaderStorageImageWriteWithoutFormat`), also without a bump. The lighting
step (6a) appended the path-tracing fields to `CaelixRenderOptions` (`mode`
.. `frame_seed`), `CAELIX_RENDER_FLAG_SKY_ON_MISS`, `CaelixRenderMode`,
`CAELIX_MAX_BOUNCES` and `CaelixGpuTimings::composite_ms`, also without a
bump. The NRD step (6b) added `CAELIX_FEATURE_STORAGE_IMAGE_READ_WITHOUT_FORMAT`
(bit 10), the debug views `CAELIX_VIEW_NRD_VALIDATION` / `CAELIX_VIEW_NRD_DIFF`,
`CaelixNrdInfo` and `caelix_renderer_get_nrd_info`, renamed
`CaelixGpuTimings::pad` to `denoise_ms` (same layout) and made
`CaelixRenderOptions::denoise` active, also without a bump. The materials step
(6d) added `CaelixMaterial`, `caelix_scene_set_materials`,
`caelix_scene_set_glass_palette`, `caelix_scene_get_material`,
`CaelixSceneStats::material_table_bytes`,
`CaelixRenderOptions::bounce_count_transparent`,
`CAELIX_MAX_BOUNCES_TRANSPARENT` and the debug views `CAELIX_VIEW_MATERIAL` (9)
and `CAELIX_VIEW_NRD_SPEC` (10), also without a bump. Rebuild hosts against the
current header.

Scene model:

- The host owns the raw voxel data. The library stores only GPU records plus a
  CPU index from brick keys to records. A brick is 8x8x8 blocks; its key is the
  entity-local block coordinate shifted right by 3.
- Record layout (1096 bytes for 16-bit blocks, follows Unity's
  `CaelixBrickTrace.hlsl` except for the pair order): 2 info words, 16
  micro-occupancy words, then the blocks two per word, even x in the low 16
  bits (the little-endian image of the `uint16` block array, so the upload is
  one memcpy). The upload writes the raw blocks and the group-local position;
  the finalize kernel fills the rest of the header and adds face bits to
  transparent blocks (see "Finalize kernel").
- Record pool: device-local pages of `records_per_page` records. Pages are only
  added, and a record never moves while its brick lives.
- Render groups of `(1 << group_shift)^3` bricks (default 16^3). Each group has
  dense 16-bit brick ids and its own range in one shared slot table buffer
  (16-byte rows: position and state, summary, record index, last used). The
  slot table buffer grows by doubling; offsets never change.
- Staging ring: one host-visible buffer (device-local too on the ReBAR path, see
  "Record upload path"). `caelix_scene_upload_bricks` writes
  records into the ring and reports how many bricks it accepted in `consumed`.
  When `consumed < count`, flush and submit the frame, then upload the rest. The
  last `capacity / 16 + capacity / 64 + 1 MiB` of the ring is reserved for table
  rows (slot rows, reverse table words, info rows, grid cells, the page table and
  the finalize list) and the record scatter entries; records cannot use it.

### Finalize kernel

`shaders/scene/caelix_finalize.hlsl` turns raw records into renderer records. Each
flush dispatches it over every brick uploaded since the previous flush and
every resident face neighbour (same entity, across groups too) of an uploaded
or removed brick: one workgroup of 64 threads per brick, one thread per row of
8 voxels. A brick is finalized at the flush after its upload; the host must not
read records or AABB rows before that flush has completed on the GPU.

Per voxel: `alive` = not all six neighbours opaque (an absent brick is air).
Opaque blocks keep their value. A transparent block gets face bit `d` (order
+X, -X, +Y, -Y, +Z, -Z) when its neighbour in direction `d` is not opaque and
has a different id; air (id 0) next to glass gets face bits too. A voxel is
occupied when it is alive and its value is not 0. The kernel writes the micro
occupancy words, the coarse byte (word 0, bits 16..23), the tight bounds (word
1) and the brick's AABB row (entity-local block coordinates; six NaNs when no
voxel is occupied, which makes it an inactive primitive).

Block encodings (`CaelixSceneDesc::encoding`): 0 = packed scene colour (the
default; opaque when `value & 0xC000`, id `value & 0xFF`, faces at bit 8),
1 = block-ID (opaque when `value & 0x8000`, id `value & 0x1FF`, faces at bit 9).

Lossless rule: `raw(v) = opaque(v) ? v : (v & id_mask)` recovers the uploaded
value from a finalized one, and the kernel always works on `raw()` of its own
and its neighbours' blocks. So finalizing a brick again gives the same record,
a neighbour may be read while another workgroup rewrites it, and dead voxels
keep their value. Uploaded transparent values must have no bits above the id.

Lookup tables (all in device-local buffers, read through buffer device
addresses; the kernel has push constants only, no descriptor sets):

- Page table: `uint64_t` device address per record page.
- Group info (32 B per group: coordinate, entity, slot row, reverse table and
  AABB row bases, high water) and entity info (32 B per entity: group grid
  minimum, dimensions and base).
- Group grid per entity: a dense array of group indices over the entity's
  group bounding box. Dimensions are powers of two and grow geometrically; the
  grid is rebuilt and fully restaged when it grows. Grids above 2^24 cells are
  refused (the upload fails with `CAELIX_ERROR_OUT_OF_MEMORY`).
- Reverse table per group: one 16-bit brick id per group-local position.
- AABB rows per group: 24 B per dense id, same capacity as the slot rows. When
  the range grows, the rows are copied on the GPU and the new part is filled
  with NaN; a removed brick's row is set to NaN.

All pools grow by doubling with a copy at the next flush, like the slot table.
Small table updates are staged as runs that also cover short clean gaps,
because every `vkCmdCopyBuffer` region has a fixed GPU cost.

### Record upload path

Uploaded records do not go through `vkCmdCopyBuffer`: one region per record costs about 1 us on the
transfer engine (18,432 records = ~17 ms). `caelix_scene_upload_bricks` writes each record into the
staging ring and a 16 B scatter entry (ring offset / 8, flags, destination address) into an entry
block of the ring (4096 entries, 64 KiB, from the row reserve). The flush runs the record scatter
kernel (`shaders/scene/caelix_record_scatter.hlsl`, one dispatch per block, 16 records per 256-thread
workgroup) before the table copies. A record that replaces a resident brick keeps its word 1 (flag
`kScatterKeepBoundsWord`). `caelix_scene_create` chooses one of two paths
(`CaelixSceneStats::upload_path`):

- ReBAR (1): the ring is in device-local, host-visible memory; the CPU writes records straight into
  VRAM and the kernel reads the ring by device address. Chosen when a device-local, host-visible
  heap of at least 1 GiB (a resized BAR; an unresized one is 256 MiB) has budget for the ring.
- Bounce (2): the ring stays in host memory. The flush copies the ring ranges of the window's
  records and entry blocks into a device-local bounce buffer at the same offsets (one
  `vkCmdCopyBuffer` with few regions), and the kernel reads that. Extra VRAM: the ring's size.

`CAELIX_UPLOAD_PATH` = `auto` | `bar` | `bounce` overrides the choice. `caelix_upload_bench`
measures the whole flush (records, table copies, finalize, BLAS/TLAS) with 18,432 replaced records
per frame on the RTX 5080: 15.3 ms with copy regions, 0.31 ms ReBAR, 1.19 ms bounce.

### Light tree

Light bricks, brick light records, the static and dynamic light BVHs and the device API that draws
a light point with its pdf (`caelix_scene_set_light_options`, `shaders/light/caelix_light_tree.hlsl`):
[`docs/LIGHT_TREE.md`](docs/LIGHT_TREE.md). Test: `caelix_light_tree_test`.

### Light NEE

Next-event estimation of the light voxels: every diffuse vertex with a next segment draws one lamp
point from the light tree for its own point and normal, one shadow ray is chosen between it and the
sun candidate, and the next BSDF hit on a lamp is weighted by MIS with the exact light tree pdf; no
memory between frames or pixels (`caelix_renderer_set_light_nee_options`, the NEE in
`shaders/render/caelix_path_trace.hlsl`, `shaders/render/caelix_light_nee.hlsl`; frames without light
NEE bind the kernel variant `caelix_path_trace_no_light_nee`): [`docs/LIGHT_NEE.md`](docs/LIGHT_NEE.md).
The light cells of the first version (removed 2026-10-24) are in its history section. Tests:
`caelix_light_nee_test`, the "light NEE" cases of `caelix_trace_test`.

### Subsurface scattering

Opaque materials with `sss_model` = `CAELIX_SSS_MODEL_HG`, `sss_probability` > 0 and `sss_steps` > 0
are SSS voxels: with `CAELIX_RENDER_FLAG_SUBSURFACE` a path vertex on one runs, with probability
`sss_probability`, a Henyey-Greenstein lattice walk through the voxels of its entity instead of the
surface BSDF; the exit is a diffuse vertex (`shaders/render/caelix_subsurface.hlsl`). The transmissive
shadow ray (`CAELIX_RENDER_FLAG_SHADOW_TRANSMISSION`, [`docs/SHADOW_TRANSMISSION.md`](docs/SHADOW_TRANSMISSION.md))
passes SSS voxels in a straight line. All subsurface code lives in the trace kernel variants
`caelix_path_trace_sss` and `caelix_path_trace_sss_no_light_nee` (`CAELIX_SUBSURFACE 1`); the renderer
binds them for the lighting frames of a scene whose material table has an SSS entry, so the main
kernels `caelix_path_trace` / `caelix_path_trace_no_light_nee` carry no SSS code:
[`docs/SUBSURFACE.md`](docs/SUBSURFACE.md). Tests: the "subsurface" cases of `caelix_trace_test`.

### Hash table

A reusable GPU hash table (64-bit keys -> payload indices, `lib/src/rhi/hash_table.h`,

### Acceleration structures

Each flush builds the acceleration structures after the finalize kernel
(`Scene::PlanAccelerationStructures` and `RecordAccelerationStructureBuilds` in
`lib/src/scene/scene_accel.cpp`). The renderer binds the TLAS (see "Renderer").

- BLAS per render group: procedural AABB geometry
  (`VK_GEOMETRY_TYPE_AABBS_KHR`, `VK_GEOMETRY_OPAQUE_BIT_KHR`) over the
  group's AABB rows, stride 24, `primitiveCount` = the group's high water. Free
  ids and bricks without occupied voxels have NaN rows, which are inactive
  primitives. Build flag `PREFER_FAST_TRACE` only, mode BUILD; refit
  (`ALLOW_UPDATE`) and compaction come later.
- TLAS per scene: one instance per live group that has a BLAS.
  `instanceCustomIndex` = the scene-wide group index (24 bits, so a scene
  holds at most 2^24 groups), mask 0xFF, SBT record offset 0,
  `FORCE_OPAQUE`, transform = the entity transform (unit quaternion and
  position, scale 1) as a 3x4 row-major matrix: the AABBs are in
  entity-local block coordinates. The instance array is rebuilt on the CPU,
  staged through the ring and copied to a device-local buffer.
- Storage (`lib/src/rhi/alloc/as_pool.h`, `BlockAllocator`): an acceleration structure
  must never move (the TLAS refers to BLASes by device address), so it does
  not use `RowPool`. Storage comes in 64 MiB device-local chunks
  (`ACCELERATION_STRUCTURE_STORAGE | SHADER_DEVICE_ADDRESS`) that are only
  added. Blocks come from power-of-two size classes from 4 KiB, with one free
  list per class per chunk and a bump pointer per chunk; a block larger than a
  chunk gets a chunk of its own. A structure is rebuilt in place when its
  block is large enough (safe: one queue, and the flush starts with a barrier
  from all earlier commands). Otherwise it gets a new block and a new handle;
  the old block and handle are released when the safe frame reaches the
  flush, because a TLAS of a frame in flight may still refer to them. The
  BLAS of a freed group is released after the TLAS build that drops it.
- Scratch budget: one buffer of `CaelixSceneDesc::scratch_bytes` (default
  128 MiB), bump-allocated per flush with
  `minAccelerationStructureScratchOffsetAlignment` (128 on an RTX 5080). The
  TLAS takes its scratch first (sized for an instance per live group), then
  BLASes in first-come order until one does not fit; the rest wait for the
  next flush. The buffer grows when the TLAS and the largest single BLAS do
  not fit together. Builds are recorded in calls of up to 256 infos.
- Rebuild policy: a group's BLAS is out of date when one of its bricks is
  queued for finalization (its own upload, or the upload or removal of a
  face neighbour) or removed. It is built in the first flush in which its AABB
  rows are final: its table rows were staged and none of its finalize entries
  wait for a later flush. The TLAS is out of date when a BLAS was built, a
  group with a BLAS was freed, or an entity was moved or removed. Every BLAS
  build invalidates the TLAS, so BLASes are built only in a flush that also
  builds the TLAS: when the ring has no room for the instances, all builds
  wait.
- Barriers inside the flush: the first barrier now goes from all earlier
  commands to all commands (it also covers in-place rebuilds and the reused
  scratch); after the copies and the kernel, transfer and compute writes ->
  all commands; after the BLAS builds, `AS_BUILD` write -> `AS_BUILD` read;
  after the TLAS build, `AS_BUILD` write -> all commands, memory read.
- Entity transforms on the GPU: the entity info row is 128 bytes (grid fields,
  then the current and the previous object-to-world rows as `float4` x 3
  each). `prev` differs from `cur` for exactly one flush after
  `caelix_scene_set_entity_transform`; the trace kernels read both for motion
  vectors.

What the host can query: `CaelixSceneStats` (`blas_count`, `blas_bytes` and
`tlas_bytes` including blocks that wait for a safe frame, `scratch_bytes`,
`as_builds_total`, `as_builds_pending`), the BLAS of a brick's group and the
entity info row through `caelix_scene_query_brick`, and the TLAS handle and
address through `caelix_scene_get_tlas` (owned by the library; it can change
at any flush). A brick is traceable in the commands recorded after the flush
that finalizes it when the scratch and ring budgets allowed its group's build;
`as_builds_pending == 0` tells the host that every structure matches the
uploaded bricks.

### Shaders

HLSL in `shaders/` is compiled at build time by DXC (`$VULKAN_SDK/Bin/dxc.exe`,
`-T cs_6_6 -spirv -fspv-target-env=vulkan1.3 -HV 2021 -O3 -WX`) to
`build/shaders/<name>.spv`, then embedded into the library as `uint32_t` arrays
(`cmake/Shaders.cmake`, `cmake/EmbedShaders.cmake`). DXC writes a depfile, so
an edit of an included header rebuilds the kernels that include it. The SPIR-V
does not depend on the C++ configuration. `shaders/common/caelix_platform.hlsl` is the
only file with DXC-specific syntax (buffer device address loads and stores,
push constants, descriptor bindings, attributes); a Slang port replaces this
header. Storage images that are written without a format qualifier need
`CAELIX_FORMAT_UNKNOWN` (`[[vk::image_format("unknown")]]`): without it DXC 1.8
infers the format from the element type (`RWTexture2D<float4>` becomes
`Rgba32f`), and it has no command-line switch to stop that.

At scene creation (and renderer creation) the library loads each kernel by name. When the environment
variable `CAELIX_SHADER_DIR` names a directory that contains `<name>.spv`, that
file is used instead of the embedded array (logged at info level as
`shader <name> loaded from <path>`), so a shader can be changed without
rebuilding the library.

Profiling: configure with `-DCAELIX_SHADER_DEBUG_INFO=ON` to compile every kernel with DXC `-Zi`
(the HLSL source and line markers in the SPIR-V), so Nsight maps SASS, samples and live registers to
source lines. The code is the same: `caelix_path_trace` keeps its register count and occupancy (Nsight
GPU Trace, 2026-10-22). Only the `.spv` grows (about 2x). Default `OFF`. DXC 1.8 crashes with `-Zi` on
the depfile command and with `-fspv-debug=vulkan*` at `-O3`, so the option adds `-Zi` to the compile
command only.

Specialization hook (measurements only): `caelix_path_trace.hlsl` has `SpecializeFrameConstants`,
which replaces frame constant fields by constants when a `CAELIX_SPEC_*` macro is defined (DXC `-D`),
so the compiler removes the code they select: `CAELIX_SPEC_NO_RR_GUIDES` (no DLSS RR guides),
`CAELIX_SPEC_NO_PRIMARY_MODE` (a primary-mode frame renders as path trace; `lighting` is then
`true`), `CAELIX_SPEC_PT_ONLY` (path trace mode, debug view 0), `CAELIX_SPEC_NO_FOG`,
`CAELIX_SPEC_NO_SKY_CUBEMAP`, `CAELIX_SPEC_FLAGS_MASK=<bits>` (keeps only those render flags),
`CAELIX_SPEC_BOUNCES_TRANSPARENT=<n>` and `CAELIX_SPEC_NO_SUBSURFACE` (clears the subsurface flag: the
walk of the `caelix_path_trace_sss*` variants folds away). A kernel built with them is valid only for frames whose
options match. The build defines none: the default SPIR-V is byte-identical to the source without
the hook. `Claude/regstat.py` (outside the repo) compiles the kernel with them and loads it through
`CAELIX_SHADER_DIR` with `CAELIX_PIPELINE_STATS` to read the register count.

Frame contract: call `caelix_scene_flush` once per frame with a command buffer
in the recording state, a strictly increasing `frame_number` (1 or higher), and
`safe_frame_number` = the newest frame that has completed on the GPU (0 = none).
The flush records the staging-to-pool copies, the finalize dispatch and the
acceleration structure builds between barriers. Staging space, replaced GPU
buffers and replaced acceleration structures of a frame are released only
when that frame is safe. `caelix_scene_recycle(safe)` releases them without a flush, for a host
that waits for a frame and then uploads before the next flush. Destroy every
scene before `caelix_device_destroy`, with the device idle.

When a flush records work, it brackets that work with two timestamp queries
(`lib/src/rhi/gpu_timer.h`); the time is reported as `flush_ms` by
`caelix_renderer_get_gpu_timings` (0 for a flush that recorded nothing).

### Renderer

`caelix_renderer_create(device, scene)` creates a renderer for one scene
(`lib/src/render/renderer_*.cpp`). `caelix_renderer_render(renderer, frame, targets,
camera, options)` records the frame's rendering. Call it after
`caelix_scene_flush` of the same frame, with the same `CaelixFrameDesc`: the
flush builds the TLAS that the render binds.

- Modes (`CaelixRenderOptions::mode`): `CAELIX_MODE_PRIMARY` (debug views of
  the primary hit, one dispatch), `CAELIX_MODE_PATH_TRACE` (path-traced
  lighting, raw 1 sample per pixel) and `CAELIX_MODE_REFERENCE` (the same,
  accumulated over frames). See "Lighting" below.
- Trace kernel `shaders/render/caelix_path_trace.hlsl`, `[numthreads(8, 8, 1)]`:
  one primary ray per pixel, `RayQuery<RAY_FLAG_FORCE_OPAQUE>` through the
  TLAS (`TraceScene`, also used by the bounce rays). For every procedural
  candidate it reads the group info (`CandidateInstanceID()` = the group
  index) and the slot row of the dense brick id (`CandidatePrimitiveIndex()`),
  skips bricks that are not resident, and runs the brick DDA on the record. A
  hit inside `[TMin, CommittedRayT())` is committed. Then it writes every
  present target (see "Render targets" below). A miss writes the sky colour
  and the miss values. In the lighting modes it also shades the hit and
  traces the bounces into the internal targets.
- Composite kernel `shaders/render/caelix_composite.hlsl`, `[numthreads(8, 8, 1)]`,
  lighting modes only: internal targets -> the host's colour target. With the
  delta checkerboard (path trace mode) it writes an internal RGBA16F resolve
  image instead, and the cross resolve kernel
  `shaders/render/caelix_cross_resolve.hlsl` (same descriptor set,
  `render/caelix_composite_set.hlsl`) writes the colour target; see "Materials
  and glass (step 6d)".
- NRD (`lib/src/render/nrd_executor.*`, path trace mode with `denoise = 1`): NRD's
  own compute dispatches between the trace and the composite (see "Denoising
  (step 6b)" below).
- Sky SH kernel `shaders/render/caelix_sky_sh.hlsl`, one workgroup of 256, lighting
  modes with a host sky cubemap only: projects the cubemap onto 9 irradiance SH
  coefficients before the trace (see "Sky cubemap, fog, emission scale" below).
- Shading helpers `shaders/render/caelix_shading.hlsl`: block colours (debug
  views), the random stream, the shading rule (opaque and transparent), the
  interface decision of the delta chain, the medium extinction, the fog of the
  air and the sky (procedural or the host's cubemap). Materials come from the
  scene's material table
  (`shaders/common/caelix_material.hlsl`, see "Materials and glass (step 6d)").
- Scene traversal `shaders/render/caelix_scene_trace.hlsl`: the TLAS binding, the
  ray-query loops `TraceScene` / `TraceShadow` (brick DDA on every procedural
  candidate), the slot-row / page-table record lookup and the entity transform
  helpers (`EntityCurWorld`, `EntityPrevWorld`). Everything the integrator knows
  about the scene's tables goes through this file.
- Brick DDA `shaders/render/caelix_brick_trace.hlsl`: a copy of Unity's
  `CaelixBrickTrace.hlsl` (2-level occupancy DDA on the 8^3 brick, tight
  bounds from record word 1, transparency by face bits). Every change is
  marked `// NATIVE:`: no Unity includes (`caelix_block.hlsl` decodes the
  block by the scene's encoding at run time); the record loads read through
  the record's device address (`g_recordBase`, set per candidate, `brickBase`
  0); `CaelixTraceBrickPrimitiveCore` takes the brick origin in entity-local
  block coordinates as a parameter instead of deriving it from word 0 and the
  render group macros; `half` = float, `UNITY_BRANCH` -> `CAELIX_BRANCH`.
- Inputs: two descriptor sets and no push constants. Set 0 is the kernel's own set: for the
  trace kernel binding 0 the TLAS, bindings 1..7 the colour,
  albedo, normal, depth, motion, view_z and voxel_id targets as storage images without a
  format qualifier, bindings 8..19 the internal targets of the lighting modes
  with fixed formats, binding 20 the sky cubemap as a sampled image and 21 its
  sampler (`lib/src/render/render_kernels.h`; the output-size pass `caelix_voxel_id`, which writes
  the voxel id target and an output-size depth target under an upscaler, binds the
  same set). Set 1 is the frame set, shared by the six
  frame-constant kernels (`caelix_path_trace`, `caelix_composite`, `caelix_cross_resolve`,
  `caelix_sky_sh`, `caelix_upscale_encode`, `caelix_voxel_id`): binding 0 the frame slot's 608-byte
  `CaelixFrameConstants` block as a uniform buffer (`g_frame`, `shaders/common/caelix_frame_ubo.hlsl`,
  `shaders/common/caelix_frame.hlsl`, `lib/src/render/frame_constants.h`; `kFrameSetIndex`).
  A uniform buffer is read-only, so the compiler re-reads a field where it is used instead of
  keeping the struct live in registers across the traces, as it did for the struct loaded through
  a buffer device address (registers on the RTX 5080, driver 610.88: trace 128 -> 96, composite
  40 -> 22, cross resolve 40 -> 34, sky SH 48 -> 45, encode 29 -> 18; trace -0.8 .. -1.5 ms at
  2560x1440, `Artifacts/main-ubo-20261022`). Its layout is DXC's default constant buffer layout,
  which gives the C offsets only while every field sits at a multiple of its size, no vector
  crosses a 16-byte row and every array element is 16 bytes; `caelix_frame_layout_test` checks
  the compiled kernels. The block holds the camera, target size, the addresses of the page
  table, slot tables, group infos, entity infos and the material table, the record layout, group
  shift, encoding, view, flags, sun and sky, the rows of the host projection,
  the previous render call's camera, the present-target mask, the miss values,
  `has_prev_camera` / `has_tlas`, and the lighting parameters (mode, bounces,
  seed, accumulation count, exposure, sun and sky, sRGB output, `t_max`, fog,
  emission scale, sky cubemap parameters and the SH buffer address). The
  composite and cross resolve kernels share set 0 (binding 0 the colour target, bindings 1..9
  internal targets and the upscale input, 10 the sky cubemap, 11 its sampler), the sky SH kernel
  has the cubemap and its sampler, the encode kernel three storage images; each binds the frame
  set as set 1. Every binding is `PARTIALLY_BOUND`
  (`VkDescriptorSetLayoutBindingFlagsCreateInfo`): a render call writes only the
  TLAS (when the scene has one) and the present targets, and the kernel touches
  a binding only when its bit is set. Absent targets and a scene without a TLAS
  therefore need no dummy descriptors. The sky bindings are written every call
  (the host's cubemap or a 1 x 1 fallback cube that is never sampled).
- Per-frame resources: a ring of slots (five descriptor sets: trace, composite,
  sky SH, encode and the frame set; + a host-visible constants buffer with `UNIFORM_BUFFER` usage,
  which the slot's frame set points at, written once when the slot is created), 3 at first, grown
  up to 8 when a slot's frame is not safe yet.
- Image views: one per target image and one cube view per sky cubemap, cached
  (16; the least recently used view is destroyed once its frame is safe).
  `caelix_renderer_release_target_views` destroys all of them; call it before the host destroys target images (a new
  image can reuse the handle of a destroyed one).
- Before the scene's first TLAS build, the kernel still runs but does not
  start a ray query (`has_tlas` = 0): every pixel gets the sky colour and the
  miss values. The targets need `STORAGE` usage only.
- Debug views (`CaelixRenderOptions::debug_view`): albedo (optionally Lambert
  shaded with `sun_dir`), world normal, depth (`near_z`..`far_z`), hash colour
  of the group, hash colour of the brick, and a heat map of the procedural
  candidates per ray (0..64). Albedo in the packed encoding: opaque rgb5,
  emissive rgb4, glass a fixed tint (0.6, 0.8, 1.0), air magenta (a primary
  ray should never report an air boundary). In the block-ID encoding the
  colour is a pastel hash of the id. The material view (`CAELIX_VIEW_MATERIAL`)
  shows the material table's albedo instead: mixed 50 % with blue (0.2, 0.45, 1)
  for transparent codes, 50 % with white for emitters, air magenta.
- GPU timings: two timestamps around each dispatch, read back in
  a later render call whose safe frame has reached that frame;
  `caelix_renderer_get_gpu_timings` returns `trace_ms` (with the sky SH dispatch
  when there is a cubemap), `denoise_ms` (0 for
  a frame without NRD), `composite_ms` (0 in the primary mode; includes the
  cross resolve), `flush_ms` and
  the frame they belong to.

Pixel mapping: pixel (px, py), row 0 = the top row,
`ndc = ((px + 0.5) / w * 2 - 1, 1 - (py + 0.5) / h * 2)`, direction
`normalize(right * ndc.x * tan_half_fov_y * aspect + up * ndc.y * tan_half_fov_y + forward)`.
The camera basis is Unity's (+X right, +Y up, +Z forward); the host's
`camera.rs` builds it from Unity's `eulerAngles` (see "Running the host").

### Lighting (step 6a)

The lighting modes port the opaque part of Unity's path tracer
(`CaelixPathTraceCommon.hlsl`: `CaelixShadeVoxelHit` and the bounce loop).
`CAELIX_MODE_PATH_TRACE` shows the 1 spp estimate (denoised by NRD with
`denoise = 1`, see "Denoising (step 6b)") and `CAELIX_MODE_REFERENCE` the running
mean of the raw estimate.

- Primary hit (after the delta chain, see "Materials and glass (step 6d)"):
  the material from the scene's material table (packed: opaque rgb5 / 31,
  emissive rgb4 / 15 with `emission = albedo * 2^(3 * strength)`, the glass
  palette; block-ID: the pastel hash colour until the host sets a table) is
  shaded with Unity's rule: specular chance
  `lerp(metallic, 1, fresnel * smoothness)` (0 for packed opaque materials, so
  they are diffuse only), cosine-weighted diffuse direction `normalize(N + unit)`,
  `k = 1`, origin pushed off 0.002 along N (Unity's `K_RAY_ORIGIN_PUSH_OFF`).
  Its emission goes to the deterministic target.
- Bounces: up to `bounce_count` (0..14, Unity default 4) segments of length
  1e4 (`K_T_MAX`). A miss adds `SkyRadiance(dir) * throughput` and stops; a hit
  adds `emission * throughput`, multiplies the throughput by the albedo, and
  Russian roulette on the largest throughput channel may stop the path. The
  incident radiance goes to the diffuse or the specular target by the lobe of
  the primary hit, packed for NRD REBLUR
  (`REBLUR_FrontEnd_PackRadianceAndNormHitDist`: YCoCg radiance, alpha = the
  hit distance of the first segment normalized by
  `REBLUR_FrontEnd_GetNormHitDist` with A, B, C = 3, 0.1, 20 at the primary
  view z, roughness 1 for the diffuse lobe; 1e4 before normalization when the
  segment reaches the sky, 0 when there is no segment). The lobe that was not
  sampled gets 0 radiance and 0 hit distance. NaN or Inf drops the sample;
  values are clamped to 65504 (FP16).
- Transparent blocks: the delta chain and the transparent shading branch, see
  "Materials and glass (step 6d)".
- Random numbers: `PcgHash(px ^ (py << 16) ^ (frame_seed * 0x9E3779B9))`,
  then xorshift32 (Unity samples a blue-noise texture). The host must change
  `frame_seed` every frame.
- Sky: above the horizon `lerp(horizon, zenith, sqrt(dir.y))`, below it
  `lerp(horizon, ground, sqrt(-dir.y))`, plus `sun_radiance` inside the sun
  disk (`sun_angular_radius` r, default 0.5 degrees). The disk subtends
  `omega = 2 pi (1 - cos r)` (2.39e-4 sr at 0.5 degrees), so a surface facing
  the sun receives the irradiance `sun_radiance * omega`.
- Sky cubemap, fog, emission scale (`CaelixRenderOptions::sky`, `fog_density`,
  `fog_color`, `emission_scale`): a host cubemap replaces the procedural sky
  (primary misses and the delta chain's sky end at mip 0, specular bounce misses
  at mip `roughness * (mip_levels - 1)`, diffuse bounce misses the L2 SH irradiance
  / pi); the air is a homogeneous fog on every segment that ends on a surface;
  every material emission is multiplied by `emission_scale`. See
  `docs/STEP6_LIGHTING.md`, "Sky cubemap, fog, emission scale (2026-10-16)".
- Sun next-event estimation (`CAELIX_RENDER_FLAG_SUN_NEE`, the host's
  default; skipped when `sun_radiance` is 0): every vertex that sampled the
  diffuse lobe and has a next segment (the primary hit when
  `bounce_count >= 1`, a bounce hit while segments remain) samples a direction
  `L` uniform in the sun cone (`cos theta = 1 - u1 (1 - cos r)`,
  `phi = 2 pi u2`) and traces a shadow ray (`TraceShadow`: the first DDA hit in
  range ends the ray query). Unoccluded, it adds
  `sun_radiance * omega * dot(N, L) / pi * throughput` (demodulated, like the
  bounces; before Russian roulette). The segment that leaves such a vertex sees
  the sky WITHOUT the disk, a segment that leaves a specular-lobe vertex (no
  NEE there) sees it, so the sun is counted once per path. A primary miss
  always shows the disk. NEE draws from its own random stream
  (`InitRandom(pixel, frame_seed ^ 0x68E31DA4)`), so the BSDF path consumes the
  same random numbers with NEE on or off. Without the flag the sun is found
  only by chance (6a behaviour, as in Unity): a small disk then needs a very
  high radiance, which does not converge.
- Composite: diffuse and specular are unpacked with
  `REBLUR_BackEnd_UnpackRadianceAndNormHitDist` (NRD's outputs when the frame
  was denoised, else the raw packed inputs); `raw = deterministic + albedo *
  (diffuse + specular)`; reference
  mode `accum = n == 0 ? raw : lerp(accum, raw, 1 / (n + 1))`; then `* exposure`;
  a miss is `SkyRadiance(primary direction) * exposure` with
  `CAELIX_RENDER_FLAG_SKY_ON_MISS`, else 0; alpha = coverage; linear -> sRGB
  for UNORM colour formats.
- Accumulation count `n`: 0 after `reset_accumulation`, a mode change, a size
  change (the internal targets are recreated) and on the first render; +1 per
  reference render with a colour target.
- Internal targets (owned by the renderer, `STORAGE | SAMPLED`, layout
  `GENERAL` after one transition, recreated when the host target size changes;
  the old ones are destroyed once their last frame is safe):

| Target | Format | Content |
|---|---|---|
| `view_z` | R32F | linear view depth; 1e30 on a miss (NRD `IN_VIEWZ`) |
| `normal_roughness` | RGB10A2 | `NRD_FrontEnd_PackNormalAndRoughness(N, 1 - smoothness, 0)` (`IN_NORMAL_ROUGHNESS`) |
| `motion` | RGBA16F | motion in pixels (xy), previous view z - view z (z) (`IN_MV`) |
| `albedo` | RGBA8 | material albedo; a = coverage |
| `deterministic` | RGBA16F | primary emission |
| `diff_in`, `spec_in` | RGBA16F | REBLUR-packed incident radiance and normalized hit distance (`IN_DIFF/SPEC_RADIANCE_HITDIST`) |
| `accum` | RGBA32F | reference accumulation |
| `diff_out`, `spec_out` | RGBA16F | NRD's outputs (`OUT_DIFF/SPEC_RADIANCE_HITDIST`) |
| `validation` | RGBA8 | NRD's validation layer (`OUT_VALIDATION`) |

### Materials and glass (step 6d)

Design and owner decisions: `docs/STEP6D_MATERIALS_DELTA.md` (section "As built").

- Material table: every scene has 65536 `CaelixMaterial` entries (112 bytes:
  albedo, smoothness, emission, metallic, ior, extinction, plus subsurface
  fields (read by the subsurface walk and the transmissive shadow ray,
  `docs/SUBSURFACE.md`) and texture fields that no kernel reads yet), one per
  16-bit block code. The GPU
  holds two packed tables (`docs/MATERIALS.md`): 32-byte hot entries of halves
  in a 2 MiB device-local buffer whose address is in the frame constants
  (`materials`, offset 440), and 32-byte subsurface entries in a second 2 MiB
  buffer (`subsurface_table`, offset 560). The kernels read the hot table with `GET_MATERIAL(code)`
  (`shaders/common/caelix_material.hlsl`); a transparent code loses its face
  bits first. The CPU copy (`lib/src/scene/material_table.*`) is built per
  encoding at scene creation: packed = the old shader decode for opaque and
  emissive codes, the glass palette for transparent codes (ids 1..132 from
  `data/glass-palette.json`, a copy of Caelix's `Tools~/RawColor/glass-palette.json`,
  through the generated `glass_palette_default.inc`; air and ids 133..255 are
  the vacuum entry albedo 1, smoothness 1, ior 1, extinction 0, as Unity's
  `GetSharedGlass` default); block-ID = the pastel hash colours. The host
  replaces the whole table (`caelix_scene_set_materials`) or, in packed
  scenes, the glass palette (`caelix_scene_set_glass_palette`), and reads
  entries with `caelix_scene_get_material`. Changed chunks of 1024 entries
  (32 KiB per table, both tables together) are staged at the next flush after
  everything else (lowest priority; a chunk that does not fit waits); the first
  flush zero-fills both buffers.
- Delta chain (`CaelixRenderOptions::bounce_count_transparent`, Unity default
  5, host default 5): after the primary hit, every smooth transparent hit
  (smoothness >= 0.99, not opaque) is an interface; up to that many are crossed.
  At each the ray reflects or refracts (Unity's `AdvanceDeltaRay`: normal
  flipped against the ray, `eta = ior_from / ior_to`, air = ior 1, refraction
  chosen with probability `1 - FresnelReflectAmountTransparent`, total internal
  reflection always reflects, k = 1, origin pushed off 0.002 to the side of the
  new direction). Every segment inside a medium is attenuated by
  `exp(-(1 - albedo) * t * extinction)` of that medium. Opaque surfaces always
  end the chain (owner decision: smooth metals reflect through the stochastic
  specular lobe, as in Unity). The first hit that is not crossed is the primary
  surface (primary surface replacement): the G-buffer (albedo, normal, motion)
  describes it, its depth and view z are the chain length along the camera ray,
  its motion is the virtual point moved by the surface's own motion, and its
  shading, emission and bounces are multiplied by the chain's transmission (the
  composite's albedo and deterministic targets carry it). A chain that leaves
  the scene after an interface writes `transmission * SkyRadiance(dir)` (sun
  disk included) to the deterministic target, coverage 1, internal view z 1e30
  (NRD ignores the pixel), host depth from the chain length to the last
  interface. NRD lobe: a pixel whose camera ray crossed an interface goes to the
  specular target with roughness 0 (build switch `CAELIX_PSR_LOBE` 0, the
  default; 1 = only a first-interface reflection does, a refraction keeps the
  surface's lobe). The chain draws its random numbers from the path's stream;
  an opaque scene draws none, so its images are unchanged.
- Transparent shading (a rough transparent surface, or any hit after the
  chain's budget, and every transparent hit of a bounce): Unity's transparent
  branch of `CaelixShadeVoxelHit`: perfect reflection or refraction chosen by
  Fresnel (whatever the smoothness), albedo 1, the block's emission, the
  specular lobe with roughness 0, the medium of the outgoing ray tracked into
  the bounce loop, where every segment is attenuated by its medium (a miss has
  T = 0, so the sky is not attenuated). Sun NEE runs at diffuse vertices only;
  shadow rays treat glass as opaque.
- Delta checkerboard (`CAELIX_RENDER_FLAG_DELTA_CHECKERBOARD`, path trace mode
  only, host default on, Unity parity): at the FIRST interface of the chain,
  when refraction exists, even pixels (`(px + py) % 2 == 0`) refract and odd
  pixels reflect, and the branch carries the weight `2 (1 - F)` or `2 F` (no
  random number is drawn); total internal reflection stays unsplit. Later
  interfaces keep the random choice. A split pixel is flagged in the internal
  motion target's w (and in the host motion target's w for RGBA formats). The
  RGBA8 albedo target stores half of a split pixel's albedo (the weight can
  reach 2) and the composite doubles it. The composite then writes its linear
  output (after the exposure) into an RGBA16F resolve image, and the cross
  resolve (a port of Unity's `CaelixCrossResolve`) writes the host target: a
  flagged pixel becomes `0.5 * centre + 0.125 * each flagged orthogonal
  neighbour`, renormalized (neighbours clamped at the image edge); unflagged
  pixels and alpha pass through; then the sRGB encode and the NRD validation
  overlay (moved here from the composite, so the blend is linear). The motion
  debug view passes through. Reference mode ignores the flag: a fixed branch per
  pixel would accumulate to a checkerboard, not to the image.
- Debug views: `CAELIX_VIEW_MATERIAL` (primary mode) and `CAELIX_VIEW_NRD_SPEC`
  (path trace mode, the denoised specular radiance, like `CAELIX_VIEW_NRD_DIFF`).

Measured 2026-10-14 (tests below, fixture images in
`Artifacts/native-renderer-step6d-20261014/`): the glass slab, extinction and
total internal reflection tests agree with Fresnel and Beer-Lambert within
0.7 %; the citadel is unchanged (primary overview byte-identical to step 5,
denoised detail 38.41 dB against the 6a reference, 38.42 dB before; run-to-run
NRD variation is about 57 dB). Glass under NRD on the fixture (static camera,
screenshots 5 frames apart): with the plain stochastic choice the glass boils
(frame-to-frame PSNR 19.7 dB, 20.9 dB against the reference), because the
reflect/refract flip changes the albedo and deterministic targets, which bypass
the denoiser; with the checkerboard it is stable (39.6 dB frame to frame, 27.7 dB
against the reference; opaque surfaces 60 dB). Details in the artifact README.

### Denoising (step 6b)

`CaelixRenderOptions::denoise = 1` in `CAELIX_MODE_PATH_TRACE` (with a colour
target) runs NVIDIA NRD v4.18.0, denoiser `REBLUR_DIFFUSE_SPECULAR`, between the
trace and the composite. NRD is a static library with embedded SPIR-V; the
renderer drives it without NRI through `NrdExecutor` (`lib/src/render/nrd_executor.*`):

- From `nrd::GetInstanceDesc` / `GetLibraryDesc` (nothing hard-coded): one
  pipeline layout shared by NRD's 14 pipelines, set 0 = 18 sampled images from
  binding 20 and 7 storage images from binding 3 (all `PARTIALLY_BOUND`),
  set 1 = the two immutable samplers (bindings 0, 1: nearest and linear clamp)
  and one `UNIFORM_BUFFER_DYNAMIC` (binding 2). NRD's pools are one image each
  (13 permanent, 8 transient for this denoiser; 39 + 26 MiB at 1280x720, 158 +
  105 MiB at 2560x1440), `SAMPLED | STORAGE`, moved to `GENERAL` once and kept
  there (no layout tracking; free on NVIDIA).
- Constants: a host-visible ring of 960-byte blocks (912 rounded up to the
  uniform offset alignment), `setsMaxNum` (36) blocks per frame slot, written
  only when a dispatch's data differs from the previous dispatch's. Set 1 is
  written once and bound with a dynamic offset per dispatch.
- Per frame: one descriptor pool per renderer frame slot, reset and filled
  with one set 0 per dispatch; every dispatch follows one global
  compute-to-compute memory barrier (conservative: finer per-resource barriers
  would let independent passes overlap). 8 dispatches per frame (classify
  tiles, hit distance reconstruction, pre-pass, temporal accumulation, history
  fix, blur, post-blur, temporal stabilization), 9 with the validation layer,
  32 on the first frame of an instance (the pool clears of
  `CLEAR_AND_RESTART`).
- `CommonSettings`: world-to-view = rows right, up, forward of `CaelixCamera`
  (column-major, column vectors), view-to-clip = `CaelixCamera::projection`,
  the previous render call's pair, `motionVectorScale = (1/w, 1/h, 1)` (motion
  in pixels, z = view z delta), no jitter, `denoisingRange = 1e6` (the worlds
  are at most 8192 units across; a miss has view z 1e30),
  `disocclusionThreshold = 0.01`, `frameIndex` +1 per denoised frame,
  `accumulationMode` `CLEAR_AND_RESTART` on an instance's first frame,
  `RESTART` after `reset_accumulation` or a frame without denoising, else
  `CONTINUE`; `timeDeltaBetweenFrames` from a steady clock.
- `ReblurSettings`: NRD's defaults, plus `hitDistanceParameters` (3, 0.1, 20)
  (the same as the trace kernel), `enableAntiFirefly = true`,
  `hitDistanceReconstructionMode = AREA_3X3`, `maxAccumulatedFrameNum = 30`.
- NRD has no resize: a target size change creates a new instance (new pools,
  14 pipelines again, history lost); the old one is destroyed once its last
  frame is safe.
- An NRD error (`nrd::Result`) is logged; the frame is recorded without
  denoising and that render call returns `CAELIX_ERROR_VULKAN`; the renderer
  never denoises again (`CaelixNrdInfo::failed`).
- Debug views (path trace mode): `CAELIX_VIEW_NRD_VALIDATION` (NRD's
  validation layer blended over the image), `CAELIX_VIEW_NRD_DIFF` (the
  denoised diffuse radiance without the albedo), `CAELIX_VIEW_MOTION` (the
  motion vector of the primary hit, from the internal motion target, composite
  binding 7: rgb = `(saturate(mv / 32 * 0.5 + 0.5), 0.5 * coverage)`, alpha =
  coverage, no exposure, no sRGB encode; a hit without motion is grey 0.5, a
  miss is (0.5, 0.5, 0), +-32 px saturate). The motion is per frame: at 144 fps
  an entity that moves 10 units/s at 120 units distance moves about 0.6 px, so
  slow motion is only a few UNORM steps away from grey.
- Device: NRD's shaders declare `StorageImageReadWithoutFormat` (feature bit
  10), `StorageImageWriteWithoutFormat`, `StorageImageExtendedFormats` and
  `GroupNonUniformQuad` (quad intrinsics in compute: `Device::Adopt` checks the
  subgroup properties; CMake option `CAELIX_NRD_QUAD_INTRINSICS=OFF` builds NRD
  without them). No 16-bit types, no compute derivatives (no
  `DerivativeGroupQuads` execution mode), so `VK_KHR_compute_shader_derivatives`
  is not required.

Measured 2026-10-14 (RTX 5080, release, citadel, sky light only): denoise
0.23 ms (overview) and 0.33 ms (detail) at 1280x720, 0.99 ms and 1.43 ms at
2560x1440; denoised images 40.3 dB (overview) and 38.4 dB (detail) PSNR against
the 1024-frame references, raw 1 spp 18.7 dB and 15.5 dB. Known limitation:
the sun's direct light (NEE) is part of the diffuse signal, and REBLUR blurs
hard sun shadows (its pre-pass and blur radii, 30 pixels, do not see the
shadow; NVIDIA's answer is a separate shadow denoiser, SIGMA). Images and
numbers: `Artifacts/native-renderer-step6b-20261014/`.

### Render targets and G-buffer mode

`CaelixRenderTargets` has seven targets and one input (`background`, below). Each target is optional: a target is present
when its `image` is nonzero. At least one must be present; every present target
must have the same size and a different image. Every pixel of a present target
is written on every render call, a miss included.

| Target | Formats | Content | Miss |
|---|---|---|---|
| `color` | any storage format (RGBA8, BGRA8, RGBA16F, RGBA32F) | primary mode: the debug view (albedo, optionally Lambert shaded), alpha 1 everywhere; lighting modes: premultiplied colour, a = coverage (sRGB-encoded for UNORM formats) | primary: sky colour, alpha 1; lighting: the procedural sky (`CAELIX_RENDER_FLAG_SKY_ON_MISS`) or 0, alpha 0 |
| `albedo` | RGBA8, RGBA16F | material albedo as stored in the block (sRGB), no shading; a = coverage | (0, 0, 0, 0) |
| `normal` | RGBA16F, RGBA8_UNORM (stored as n * 0.5 + 0.5) | world-space face normal; w = coverage | (0, 0, 0, 0) |
| `depth` | R32F (storage image, not a depth attachment) | device depth clip.z / clip.w of `CaelixCamera::projection`; with an upscaler it has the render size (the trace writes it) or the OUTPUT size (the unjittered output-size pass writes it at the camera ray's first hit, `docs/VOXEL_ID.md`) | `options.miss_depth` |
| `motion` | RG16F, RG32F, RGBA16F, RGBA32F | previous pixel - current pixel, in pixels of the current size; RGBA formats: z = 0, w = the delta checkerboard flag (1 = the pixel needs the cross resolve with its flagged neighbours) | (0, 0) |
| `view_z` | R32F | linear view depth dot(hit - position, forward) | `options.miss_view_z` |
| `voxel_id` | R32_UINT, R32G32_UINT | two independent 32-bit hashes of (entity, entity-local voxel) of the camera ray's first hit, transparent voxels included (`docs/VOXEL_ID.md`); with an upscaler it has the OUTPUT size and a separate unjittered pass writes it | 0xFFFFFFFF in every channel (also beyond `options.voxel_id_tmax`) |

`CaelixRenderTargets::background` is an input, not a target: a host image at the render size
(sampled, layout SHADER_READ_ONLY_OPTIMAL or GENERAL, never transitioned) that the lighting modes
write into the colour at camera-ray misses instead of the sky, without the exposure and outside the
reference mean, so that an upscaler receives a complete image (`docs/BACKGROUND.md`).

A host with its own deferred pipeline passes only the geometry targets
("G-buffer mode"): the library then writes no lighting at all.

`CaelixCamera::projection` is the host's column-major projection for the
camera's view space (x = right, y = up, z = forward). It must describe the same
frustum as `tan_half_fov_y` and `aspect` (not checked) and is used only for the
depth target. A normal-Z host passes `miss_depth` 1, a reverse-Z host 0. The
Rust host passes a reverse-Z infinite projection (`camera.rs`,
`perspective_reverse_z`; depth = near / z).

Motion: the renderer keeps the camera of its previous successful render call.
The kernel moves the hit point (entity-local) through the entity's previous
transform (`EntityInfo` prev rows, which differ from the current rows for one
flush after `caelix_scene_set_entity_transform`) and projects it with the
previous camera, with the same pinhole mapping as the ray generation. The
current pixel is the pixel centre. Sign: `motion = previous - current`. A
camera that moves +1 unit along `right` sees a static point at depth z move
left on the screen, so `motion.x = +width / (2 * tan_half_fov_y * aspect * z)`
(+11.08 px for the test camera at z = 20, 256 px, 60 degrees). The first render
call of a renderer has no previous camera and writes 0; so does a point that
was behind the previous camera.

Mapping to NVIDIA NRD (the renderer's own NRD instance uses internal copies of
these targets; a host with its own NRD integration can use these): `view_z`
is `IN_VIEWZ`; `motion` is `IN_MV` with `motionVectorScale = (1 / width,
1 / height)` and `isMotionVectorInWorldSpace = false` (NRD computes
`uvPrev = uv + mv * scale`, the same convention, top-left origin); `normal`
becomes `IN_NORMAL_ROUGHNESS` after packing with a roughness
(`NRD_FrontEnd_PackNormalAndRoughness`); `albedo` is not an NRD input but
demodulates the radiance before the denoiser and modulates it after.

### Layout contract

A render call receives every present target in the layout that its
`CaelixTargetImage::layout` names, and leaves it in `VK_IMAGE_LAYOUT_GENERAL`:
one `vkCmdPipelineBarrier2` with one image barrier per present target before
the dispatches, one after them. The last barrier makes the kernels' writes
available to all later commands. The host transitions the images from
`GENERAL` for present (or for its own use).

## Build

Requirements: Visual Studio 2022 (MSVC and its bundled LLVM/libclang),
CMake 3.30 or newer (NRD's CMakeLists needs it), the Vulkan SDK (`VULKAN_SDK`
set; its DXC compiles our shaders and NRD's, tested with DXC 1.8 from SDK
1.4.304.1), and a Rust MSVC toolchain. Keep the build directory path short:
NRD's shader build (ShaderMake) fails on very long paths.

```
cmake --preset vs2022
cmake --build --preset release
cd host-rs && cargo run -p caelix-app
```

The first CMake configure fetches the pinned dependencies (volk,
VulkanMemoryAllocator, unordered_dense, NRD v4.18.0 with its ShaderMake and
MathLib, and for the tests Catch2 and vk-bootstrap) into `build/_deps/`. NRD
builds as a static library with its SPIR-V embedded (about 16 s on the first
build); our kernels include its `NRD.hlsli` (DXC `-I <nrd>/Shaders`, where
NRD's configure also writes `NRDConfig.hlsli` with the normal and roughness
encodings).

Upscalers (DLSS): with `CAELIX_DLSS=ON` (the default on Windows) the configure also fetches
the NVIDIA NGX SDK (`NVIDIA/DLSS` tag v310.9.16, a shallow clone of about 2.3 GB on disk) into
`build/_deps/ngx-src`, links its static import library and copies the release feature DLLs
`nvngx_dlss.dll` (Super Resolution) and `nvngx_dlssd.dll` (Ray Reconstruction) next to
`caelix_renderer.dll` (and, with `CAELIX_UNITY_PLUGIN_DIR`, into the Unity plugin directory).
`CAELIX_DLSS_DEV_DLL=ON`
copies the development DLLs (watermark, debug overlay, never ship them); `CAELIX_DLSS=OFF`
builds and runs without any NGX code. The renderer then takes `CaelixRenderOptions::upscaler`
(DLSS SR keeps NRD, DLSS RR replaces it), traces at the render size that
`caelix_upscaler_query` reports and writes the colour target at the output size; the host
enables the Vulkan extensions of `caelix_upscaler_instance_extensions` /
`caelix_upscaler_device_extensions` and jitters the camera (`caelix_jitter_halton`). Design,
data flow and measurements: [`docs/DLSS.md`](docs/DLSS.md). Test: `caelix_dlss_test` (query,
jitter helpers, SR and RR smoke tests against an accumulated reference, argument checks, the
upscale cost at 1920x1080; the GPU cases skip themselves without DLSS).

## Running the host

`cargo run -p caelix-app -- [flags]`

- `--frames <N>`: exit with code 0 after N presented frames. Default: run until
  the window closes.
- `--verbose`: log level `debug` (includes the Vulkan loader and validation
  layer messages). Default level: `info`. `RUST_LOG` overrides both.
- `--resize-at <N>` (hidden test aid): after N presented frames, request a
  960x540 window size once, so the swapchain recreation path runs without user
  input.
- `--world <PATH>`: a `.cxw` world to stream into the scene. Without it the
  scene stays empty.
- `--staging-mib <N>`: size of the scene's staging ring in MiB
  (`CaelixSceneDesc::staging_bytes`). Default 64, minimum 4.
- `--group-shift <N>`: render group edge in bricks = `1 << N`. Default 4
  (16^3). The library implements 1..5.
- `--pose <X,Y,Z,PITCH,YAW>`: initial camera pose in Unity's terms: position,
  `eulerAngles.x` (pitch, positive looks down) and `eulerAngles.y` (yaw), in
  degrees. Default: the world's player pose (format version 7), else
  (0, 64, -128) with pitch 15 and yaw 0.
- `--fov <DEGREES>`: vertical field of view. Default 60.
- `--mode <primary|pt|ref>`: the rendering mode. Default `pt`.
- `--view <albedo|normal|depth|group|brick|steps|material|voxel-id|nrd-validation|nrd-diff|nrd-spec|motion>`:
  the debug view; the first six, `material` (the material table's albedo,
  transparent codes tinted blue, emitters white) and `voxel-id` (one hash colour per voxel) in the primary mode,
  `nrd-validation` (NRD's validation layer), `nrd-diff` / `nrd-spec` (the
  denoised diffuse / specular radiance) and `motion` (the motion vector, see
  "Denoising") in `pt` mode. Default `albedo`.
- `--no-denoise`: `pt` mode without NRD (the raw 1 spp image). Default: NRD on.
- `--voxel-id`: pass a voxel id target (R32G32_UINT at the window size, recreated on a resize)
  to every render call; the F1 Render window switches it. `--voxel-id-tmax <F>`: a hit farther
  than F is a miss for the voxel id target and view (default 0 = no limit).
- `--size <WxH>`: inner size of the window. Default 1280x720.
- `--warmup <N>`: `pt` mode, take `--screenshot` N frames after the world is
  complete (at least 3), so that NRD's history is warm (64 for the artifacts).
  In `pt` mode the NRD history restarts only while the world is loading;
  camera motion is followed through the motion vectors.
- `--no-shading`: primary mode, albedo without Lambert shading.
- `--bounces <N>`: lighting modes, stochastic bounces (0..14). Default 4.
- `--bounces-transparent <N>`: lighting modes, smooth transparent interfaces
  that the primary ray crosses (the delta chain, 0..15, 0 = off). Default 5.
- `--no-checkerboard`: `pt` mode without the delta checkerboard and its cross
  resolve (the random reflect/refract choice at the first interface too).
  Default: checkerboard on; the Render window has a checkbox for it.
  The debug UI's Render window has a slider for it.
- `--encoding <packed|block-id>`: the scene's block encoding. Default `packed`
  (Caelix worlds).
- `--materials <PATH.json>`: a material table, applied with
  `caelix_scene_set_materials` over the built-in table (the host reads every
  entry with `caelix_scene_get_material`, replaces the listed ones and writes
  all 65536). A JSON array of `{"id", "albedo": [r, g, b], "smoothness",
  "metallic", "emission": [r, g, b], "ior", "extinction", "transparent"}`; every
  field except `id` is optional (albedo 1, smoothness 0, metallic 0, emission 0,
  ior 1.5, extinction 0, transparent false). Block-ID mapping: an opaque entry
  goes to code `0x8000 | id` (id 0..32767), a transparent one to code `id`
  (id 0..511). Meant for `--encoding block-id` worlds.
- `--exposure <F>`: lighting modes, colour multiplier. Default 1.
- `--sun <X,Y,Z>`: direction toward the sun. Default 0.45,0.7,0.55 in the
  lighting modes, -0.45,0.8,-0.3 (the Lambert direction) in the primary mode.
- `--sun-radiance <R,G,B>` (default 0,0,0 = sun off, sky light only;
  suggested `2e4,1.9e4,1.8e4` for the default 0.5-degree disk: `omega` =
  2.3925e-4 sr, so the irradiance on a surface facing the sun is
  (4.79, 4.55, 4.31), luminance 4.58, about 3.1x the default sky's 1.48 on an
  up-facing surface, `pi * (0.2 * horizon + 0.8 * zenith)` =
  (0.94, 1.51, 2.86)), `--sun-angular-radius <DEGREES>` (default 0.5), `--sky-zenith <R,G,B>` (default 0.2,0.4,0.9),
  `--sky-horizon <R,G,B>` (default 0.7,0.8,0.95), `--sky-ground <R,G,B>`
  (default 0.25,0.22,0.2): the procedural sky, linear RGB radiance.
- `--no-sky-on-miss`: lighting modes, black instead of the sky where the
  primary ray misses.
- `--no-sun-nee`: lighting modes, no sun next-event estimation (the 6a
  behaviour: the sun is found only by the bounce rays).
- `--no-shadow-transmission`: lighting modes, the primary vertex's NEE shadow rays stop at glass and
  SSS voxels again (by default they pass them, attenuated; `docs/SHADOW_TRANSMISSION.md`).
- `--no-sss`: lighting modes, no subsurface scattering walk (by default a vertex on an SSS material,
  `"sss_model": 1` in the `--materials` JSON, runs the walk with its `sss_probability`;
  `docs/SUBSURFACE.md`). The checkbox "subsurface scattering" in the render settings does the same.
- `--sky <PATH>`: lighting modes, a lat-long (equirectangular) sky image,
  `.exr` or `.hdr`, converted on the CPU (`caelix-app/src/sky.rs`) to a
  mipmapped RGBA32F cubemap, uploaded once at start (`caelix-vk`
  `Context::create_sky_cubemap`) and passed as `CaelixRenderOptions::sky`
  instead of the procedural sky. Orientation (world Y up): the image centre
  faces +Z, u grows toward +X, the top row is up. The image must not contain
  the sun disk: the sun is `--sun` / `--sun-radiance` (a sun baked into the
  image is found by chance only and flickers); a "puresky" HDRI usually
  contains the sun. `--sky-size <N>`: face size, a power of two in 4..2048
  (default 256). `--sky-rotation <DEGREES>`: turns the image around Y
  (`u = 0.5 + atan2(d.x, d.z) / (2 pi) + DEGREES / 360`, default 0).
- `--fog-density <F>` (default 0 = no fog) and `--fog-color <R,G,B>` (default
  0.6,0.7,0.8): lighting modes, extinction of the air per world unit and the
  fog radiance (`CaelixRenderOptions::fog_density` / `fog_color`).
- `--emission-scale <F>`: multiplies the emission of every material
  (`CaelixRenderOptions::emission_scale`; the library treats 0 as 1). Default 1.
- `--load-on-key`: needs `--world`; the world file is not opened at start, the
  `L` key opens it (once). The camera starts at `--pose` or the fixed default
  pose; without `--pose` the file's player pose is applied when `L` opens it.
- `--accumulate <N>`: reference mode; the accumulation restarts whenever the
  camera changes or the world is not complete yet, and `--screenshot` is taken
  after N accumulated frames. The frame seed is the frame number.
- `--screenshot <PATH.png>`: write a PNG of the swapchain image (alpha forced
  to 255). With `--world` it is taken 3 frames after the world is complete on
  the GPU (every brick uploaded and `as_builds_pending == 0`); without
  `--world` at frame 10; with `--accumulate` after N accumulated frames.
- `--exit-after-screenshot`: exit once the PNG is written.
- `--screenshot-frame <N>`: take `--screenshot` at frame number N (the frame seed; the first frame
  at or after it once the world is complete) instead of `--warmup` frames after the load, so runs
  with different options capture the same random numbers.
- Light NEE (`docs/LIGHT_NEE.md`, on by default; it enables the light tree): `--no-light-nee` turns
  it off, `--light-no-mis` uses the exclusive rule instead of MIS. `--light-tree` builds the light
  tree also with `--no-light-nee`; `--light-min-emission <F>` sets its threshold. The Stats window
  (F1) has a "Light NEE" section (enabled, running, MIS); `--timing-frames` adds
  `light_nee: running=<0|1>` to the `timings_avg:` line.
- `--no-input`: ignore keyboard and mouse, for deterministic automated runs.
  It also disables the debug UI (no egui context, no overlay renderer).
- `--no-ui`: start with the debug UI hidden (`F1` shows it).
- `--screenshot-dir <DIR>`: directory of the PNGs of the debug UI's
  Screenshot button. Default: the directory of the executable.
- `--ui-demo`: every debug window and section starts open, and at frame 60
  entity 0 is turned to a yaw of 15 degrees (for captures of the debug UI).
  Conflicts with `--no-ui` and `--no-input`.
- `--screenshot-every <N>` (test aid): write `frame-<frame number>.png` to
  `--screenshot-dir` every N frames, starting `--warmup` frames (at least 3)
  after the world is complete (without `--world`, after frame 10). Use it with
  `--frames` to get frames N apart, for example to look for ghosting.
- `--test-entity`: add the synthetic test entity (see "Test entity and brick
  edits"). `--test-entity-at <X,Y,Z>`: its orbit centre (default: 120 units in
  front of the start camera along `forward`, 10 units below the eye).
  `--test-paused`: it starts paused. `--test-orbit-radius <UNITS>` (default
  20), `--test-orbit-speed <DEG_PER_S>` (default 30), `--test-spin-speed
  <DEG_PER_S>` (default 45).
- `--test-edits`: timed brick edits on the test entity (adds it when
  `--test-entity` is absent). `--test-edit-interval <N>` (frames, 1..120,
  default 10), `--test-edit-pattern <wave|flicker>` (default `wave`).
- `--sequence <PATH>`: a camera sequence JSON file to load at start (see
  "Camera sequencer"); Save in the Sequencer window writes it. A missing file
  is allowed (a warning; the sequencer starts empty with that path). Default
  path of the Sequencer window: `<world dir>/<world file stem>.sequence.json`
  with `--world`, else `sequence.json`.
- `--sequence-play`: needs `--sequence`; start playing at once.
- `--sequence-export <DIR>`: needs `--sequence`; export the sequence as
  `frame-NNNNNN.png` into DIR once the world is complete, then exit (exit code
  0 when every frame is written). Works with `--no-input`. Default directory
  of the Sequencer window: the sequence file without `.json`, plus `-frames`.
- `--sequence-warmup <N>`: export, frames rendered at the first frame's pose
  before the first capture (NRD and upscaler history). Default 32.
- `--sequence-samples <N>`: export, renders per exported frame (1..4096); the
  last one is captured. Default 1.

### Test entity and brick edits

`host-rs/caelix-app/src/testscene.rs`, Test window. A tool to judge the motion
vectors and NRD under a moving entity and under brick edits over time.

- The entity: a hollow box of 24^3 blocks with 2-block walls. Its entity-local
  origin is the box centre: the box covers blocks -12..=11 on every axis, that
  is bricks -2..=1 (4 per axis, because 3 bricks of 8 cannot be centred on a
  brick corner); the 8 inner bricks are air and are not uploaded, so it has 56
  bricks. Faces (packed opaque rgb5): +X red, -X green, +Y blue, -Y yellow,
  +Z cyan, -Z magenta. A 4x4 hole (x, y in -2..=1) goes through the +Z wall.
  The 2x2x2 corner cubes of the four top corners are emissive white (strength
  1).
- Animation, every frame before the flush: `t += min(dt, 0.1)` unless paused;
  position = centre + radius * (cos(t * orbit), 0, sin(t * orbit)), rotation =
  yaw(t * spin) * pitch(t * spin * 0.37). The pose goes into the entity's row
  of the Entities window and is sent with `caelix_scene_set_entity_transform`
  only when it differs from the pose sent last. A paused entity gets no call,
  so the next flush makes the previous transform equal to the current one and
  its motion vectors are 0.
- Edits, every `interval` frames (or "Step once"): `wave` = one-brick columns
  at y = -3 (keys x -4..=4, z -1..=1, under the box); a column is up while
  `(x + z - phase) mod 6 < 3`, the phase advances by 1 per tick, falling
  columns are removed (`caelix_scene_remove_bricks`) and rising ones uploaded
  (solid orange). `flicker` = the four corner bricks are uploaded again with
  the emissive cubes off (dark grey) or on: a replace, no add or remove.
  Uploads go through a queue that waits for staging ring space; a remove drops
  a queued upload of the same key. The world loader's brick count check
  excludes the test entity's bricks.
- In reference mode a pose change or an edit restarts the accumulation.
- Logs: the test line every 120 frames, and at exit the run totals since the
  world was complete (AS builds per second, finalized bricks per second, flush
  ms mean and max). Measured 2026-10-14 on the 8K citadel (release, RTX 5080):
  a moving entity costs one TLAS build per frame, flush about 0.15 ms; the
  wave adds about 60 builds/s and 240 finalized bricks/s at interval 10
  (`Artifacts/native-renderer-motion-20261014/`).

In the window, press `P` to log the current camera as a
`--pose ... --fov ...` line. With `--load-on-key`, press `L` to open the
`--world` file (the Stats window's world line says "press L to load <file>"
until then).

### Camera sequencer

`host-rs/caelix-app/src/sequence.rs`, Sequencer window. Fly around a scene,
drop keyframes, preview the tour in real time, save it as JSON and export it
as a PNG frame sequence.

Model: a sequence is a list of keyframes. A keyframe holds a pose (position,
pitch, yaw, vertical fov), a `hold` (seconds at rest at this pose) and a
`duration` (seconds of travel to the next keyframe; to the first one when the
sequence loops, unused for the last keyframe otherwise). The timeline is the
holds and the travels in list order: keyframe i starts at the sum of the
holds and travels before it. Without `loop` the length is every hold and
every travel except the last keyframe's travel; with `loop` the last travel
goes back to keyframe 0 and the time wraps.

Interpolation of the 6-vector (x, y, z, pitch, yaw, fov):

- `smooth` (default): a Catmull-Rom spline with non-uniform knots, as cubic
  Hermite segments. The velocity at a keyframe is the difference of its two
  neighbours over their travel times, so the velocity is continuous at the
  keyframe even when the travel times differ. The camera is at rest (velocity
  0) at a keyframe with a hold, and at the first and the last keyframe of a
  sequence that does not loop.
- `linear`: straight segments at constant speed.

Yaw is always taken on the shortest arc: a travel from yaw 170 to -170 turns
20 degrees through 180, not 340 degrees through 0.

JSON format (version 1; a newer version is rejected, `hold` is optional and
defaults to 0, durations below 0.01 s and an fps of 0 are clamped):

```json
{
  "version": 1,
  "name": "gallery tour",
  "interpolation": "smooth",
  "loop": false,
  "fps": 30,
  "keyframes": [
    { "position": [60.0, 21.0, 0.0], "pitch": 0.0, "yaw": 0.0, "fov": 60.0, "hold": 1.0, "duration": 2.0 },
    { "position": [60.0, 25.0, 40.0], "pitch": 5.0, "yaw": 30.0, "fov": 60.0, "duration": 2.0 }
  ]
}
```

Keys (in the window, not while a text field has the focus): `K` adds a
keyframe at the camera (after the selected one, else at the end; its travel
time is copied from the selected or the last keyframe, else 3 s) and logs it
as a `--pose` line; `Space` plays and pauses; W/A/S/D/Q/E and the right mouse
button stop a playback (the time stays). While the sequencer plays or
exports, the movement keys do not move the camera.

Export (Export button or `--sequence-export`): the frames are written as
`frame-NNNNNN.png` (from `frame-000000.png`) at the window size, without the
debug UI (the copy is recorded before the overlay). Frame f shows the
sequence at time f / fps. Frame count: `floor(length * fps) + 1` (every frame
time in [0, length]), or `round(length * fps)` when looping (times in
[0, length), so the video loops without a repeated frame). The export waits
for the complete world, then renders `warmup` frames at the first frame's pose
(NRD and upscaler history), then `samples` renders per exported frame and
captures the last one (in reference mode they accumulate into a clean offline
frame; in pt mode NRD sees repeated frames). Each captured frame waits for
the device to go idle (`caelix_vk::Context::wait_readback`), so every frame
of the tour is captured and the export runs slower than real time. A writer
thread encodes the PNGs (a queue of 8 frames). At the end the host logs
`exported N frames to <dir> in S s (W x H)` and an ffmpeg line, which the
window shows with a Copy button:

```
ffmpeg -framerate 30 -i "<dir>/frame-%06d.png" -c:v libx264 -pix_fmt yuv420p -crf 18 "<dir>.mp4"
```

Headless flow: `cargo run --release -p caelix-app -- --world <cxw> --no-input
--size 1920x1080 --sequence tour.json --sequence-export out/` exports the tour
and exits (a PNG write error exits with an error). The Screenshot button
waits while an export runs. Measured 2026-10-20 (release, RTX 5080,
p2-gallery, 640x360, pt mode): 61 frames with 8 warmup frames in 3.1 s.

### Debug UI

The host draws a debug UI with [egui](https://github.com/emilk/egui) over the
rendered image. `F1` shows and hides it. Crates: `egui` 0.36.2 and
`egui-winit` 0.36.2 in `caelix-app` (input and the UI code, `ui.rs`), `egui`
and `egui-ash-renderer` 0.13.0 (dynamic rendering, default allocator) in
`caelix-vk` (rendering, `overlay.rs`). `caelix-app` stays free of `ash`.

Six separate egui windows in egui's default style (two changes: no window
and popup shadows, window titles at 15.5 points instead of 18). Each window
can be dragged and collapsed, and each has collapsible sections. Every window
starts collapsed, except Entities when no world is open at start, Test with
`--test-*` and Sequencer with `--sequence` (`--ui-demo` opens everything). In
the Render window only the Mode and "Accumulation and screenshot" sections
start open. The Load and Save buttons open a system file dialog (`rfd`); the
host runs it after the frame, because the dialog blocks the thread.

- **Stats**: fps (1 s window), frame number, target size; the GPU times of
  the newest timed frame (trace, denoise, composite, flush,
  `caelix_renderer_get_gpu_timings`); the scene stats (entities, groups,
  resident bricks, record and slot table MiB, acceleration structure builds
  pending); the NRD line (version, size, pool MiB, dispatches) and the world
  load state.
- **Render**: every `CaelixRenderOptions` field that the command line sets:
  mode, debug view (all `CaelixDebugView` values), bounces 0..14, transparent bounces 0..15, denoise,
  sun NEE, glass checkerboard (pt mode), sky on miss, Lambert (primary mode), exposure (logarithmic,
  0.05..8); the sun as pitch (elevation, positive up) and yaw (0 = +Z, 90 =
  +X) in degrees with the resulting direction, colour plus intensity
  (logarithmic, 0..1e5; radiance = colour x intensity) and angular radius
  (0.1..10 degrees); the sky: the image file name with Load (a lat-long
  `.exr` / `.hdr`, converted at `--sky-size` and `--sky-rotation`; it replaces
  the cubemap and switches it on), "cubemap" (disabled without an image; the
  face size and mip count) and the zenith, horizon and ground colours
  (greyed out while the cubemap is in use); fog density (logarithmic, 0..1
  per unit) and colour; the materials' emission scale (logarithmic, 0..64).
  "Reset accumulation" sets `reset_accumulation` for one frame (reference and
  NRD history); in reference mode the accumulated frame count is shown.
  "Screenshot" writes `screenshot-<frame>.png` to `--screenshot-dir`.
  The command line gives the initial values; a value that the UI does not
  touch reaches the library unchanged (the sun radiance and direction are
  rewritten only when their controls change).
- **Camera**: position, pitch, yaw, vertical fov, speed; "Copy --pose" puts
  the `--pose ... --fov ...` line on the clipboard (the `P` key still logs it).
- **Entities**: the world row (file name, Load: opens a `.cxw` in place of the
  loaded world; the old world's decoder stops, the device waits idle and its
  entities are removed with `caelix_scene_remove_entity`; the camera takes the
  new file's player pose; disabled during an export), the load state, then
  one collapsible row per world entity (index, GUID, decoded
  brick count) with the position and the Unity Euler angles (pitch, yaw,
  roll, degrees, `Quaternion.Euler` order: roll, then pitch, then yaw). A
  change calls `caelix_scene_set_entity_transform` before the frame's flush;
  "Reset" sends the file's transform (the original quaternion). In reference
  mode an entity change, a camera change or an option change restarts the
  accumulation; in path trace mode NRD follows the motion. The test entity has
  a row too (GUID `test-box (synthetic)`); its animation overwrites edits
  unless it is paused.
- **Test** (bottom right, collapsed unless `--test-entity` or `--test-edits`):
  Entity (enabled = the entity is in the scene, added in front of the current
  camera or at `--test-entity-at`, removed when off; paused; orbit radius,
  orbit speed, spin speed; "Reset to start"), Edits (enabled, interval 1..120
  frames, pattern, "Step once", ticks, bricks uploaded and removed, queued
  uploads), Stats (flush ms newest and 1 s mean / max, AS builds per second,
  AS builds pending, finalized bricks per second).
- **Sequencer** (bottom centre, collapsed unless `--sequence`; see "Camera
  sequencer"): File (file name, Load, Save = a save dialog at the current
  file, New = an empty sequence at `<world stem>.sequence.json` that only Save
  writes; name, interpolation, loop, export fps), Transport (`|<`, Play / Pause, Stop, time slider), Keyframes
  (per row: select, start time, hold, travel, pose, Go, Set, Dup, x; Add at
  camera, Up, Down), Export (directory, warmup, samples, size, frame count,
  Export / Cancel, progress, the ffmpeg line with Copy). File and keyframe
  edits are disabled while an export runs.

Input: egui sees every window event first. While the pointer is over a
window (or egui drags a widget) the mouse look and the scroll wheel are
ignored; while a widget has keyboard focus WASD/QE and `P` are ignored.

Frame order: flush, render, then the screenshot copy (`readback_now`), then
the overlay (`draw_overlay`: GENERAL -> COLOR_ATTACHMENT_OPTIMAL, a dynamic
rendering pass with load and store, COLOR_ATTACHMENT_OPTIMAL -> GENERAL),
then `end_frame` (GENERAL -> PRESENT). So `--screenshot` and the Screenshot
button never contain the UI. egui texture uploads submit their own command
buffer and wait for the queue (only when egui's textures change); freed egui
textures are destroyed once their frame has completed.

Camera convention (`caelix-app/src/camera.rs`, Unity's): for yaw θ and pitch φ,
`forward = (sin θ cos φ, -sin φ, cos θ cos φ)`, `right = (cos θ, 0, -sin θ)`,
`up = (sin θ sin φ, cos φ, cos θ sin φ)`. Free camera: W/S/A/D move along
forward and right, Q/E move down and up along world Y, Shift multiplies the
speed by 8, the mouse looks around while the right button is held (0.1 degree
per pixel), and the scroll wheel scales the speed (default 100 units/s).

The host creates one `CaelixScene` after it adopts the device. With `--world`
it adds one scene entity per file entity, then streams the bricks:

- One background thread runs `CxwFile::decode_all` (parallel on the rayon pool)
  and sends each decoded sector through a bounded channel of 32 sectors. When
  the channel is full, the decoder blocks, so it cannot run far ahead of the
  uploads.
- Every frame, after `begin_frame`: `caelix_scene_recycle(safe)`, then upload
  sectors from the channel with `caelix_scene_upload_bricks` until the channel
  is empty or `consumed < count` (the staging ring is full; the rest of that
  sector waits for the next frame), then exactly one `caelix_scene_flush` into
  the frame's command buffer. Frame numbers start at 1; `safe_frame_number` is
  the frame that last used the frame slot whose fence `begin_frame` waited for.
  Then `caelix_renderer_render` traces the scene into the swapchain image
  (the swapchain has `STORAGE`, `TRANSFER_DST`, `TRANSFER_SRC` and
  `COLOR_ATTACHMENT` usage), the debug UI is drawn over it, and `end_frame`
  presents. When the swapchain was recreated, the host calls
  `caelix_renderer_release_target_views` first.
- The window title shows the GPU times once per second
  (`Caelix Renderer | trace 0.53 ms | denoise 0.23 ms | composite 0.01 ms | flush 0.00 ms | 144 fps`); the same line
  is logged at info level every 120 frames and when a screenshot is written.
  The Stats window of the debug UI shows the same values.
  At the second frame of the renderer's NRD instance the host logs one NRD line
  (`caelix_renderer_get_nrd_info`: version, size, pipelines, pool textures and
  MiB, dispatches per frame).
  Presentation uses FIFO, so the frame rate is limited by the display.
- When the decoder has
  finished and every brick is uploaded, the host logs one summary (entities,
  groups, resident bricks, record pages, GPU memory, decode and upload time,
  upload frames, bricks/s, the acceleration structure stats, the full
  `CaelixSceneStats`) and queries the first key of the first 3 decoded sectors
  with `caelix_scene_query_brick`. When `bricks_resident` differs from the
  number of decoded bricks, it logs an error and exits with a non-zero code.
- After the load, the first flush that leaves `as_builds_pending == 0` logs
  one more line: its frame number, the time since the loader opened the file,
  the frames since the first upload and since the load summary, and the BLAS,
  TLAS and scratch sizes. When `blas_count` differs from the group count, it
  logs an error and exits with a non-zero code.
- `--frames N` exits after N frames even when the load is not complete (with a
  warning). At exit the host drops the channel receiver and joins the decoder
  thread. `decode_all` cannot be cancelled: it decodes the remaining sectors and
  drops them.

Expected numbers for `VoxelTestScenes/epic-citadel.8192.packed.cxw` (release,
RTX 5080, 64 MiB staging): 3837 sectors, 1 entity, 3837 groups, 1,095,051
resident bricks in 5 record pages (1370 MiB of record pages, 32 MiB of slot
tables, 32 MiB of reverse tables, 48 MiB of AABB rows, 4 to 8 MiB of group
grid). The upload takes about 0.52 s over 39 frames, 20 of which upload (the
ring holds one frame's records until that frame is safe), about 2.1 M bricks/s;
before the acceleration structure step it took 0.38 s, and without the
finalize step 0.30 s. About 1.18 M bricks are finalized (bricks are finalized
again when a neighbour arrives in a later frame). The acceleration structures
are complete in the same flush that completes the load (frame 46, 0.56 s after
the file was opened): 3837 BLASes in 64 MiB, a 2 MiB TLAS, 128 MiB of scratch,
about 8250 builds (a group is rebuilt when a neighbour arrives later, and the
TLAS is rebuilt every upload frame). Peak working set of the process is about
0.6 GB.

Debug builds enable `VK_LAYER_KHRONOS_validation` when it is installed; its
messages are logged with target `vulkan`. Library messages use target `caelix`.
Release builds run without validation.

Implicit layers that other software installs can add loader warnings that are
not from this project. Example: the Overwolf layers report an old API version;
set `DISABLE_VULKAN_OW_OVERLAY_LAYER=1` and `DISABLE_VULKAN_OW_OBS_CAPTURE=1`
to disable them for a run.

## Environment variables

- `CAELIX_SHADER_DIR`: directory with `<name>.spv` files that replace the
  embedded kernels at scene creation (see "Shaders").
- `CAELIX_PIPELINE_STATS` (any value): diagnostics. The Rust host enables
  `VK_KHR_pipeline_executable_properties` (feature `pipelineExecutableInfo`) when the device offers
  it, and the library then creates its compute pipelines with `CAPTURE_STATISTICS` and logs the
  driver's statistics at info level, one line per kernel:
  `pipeline stats caelix_path_trace [CS]: Register Count = 255, Binary Size = ..., Local Memory Size = ...`.
  This is the register count of the code that runs; an Nsight capture can show a different
  compile. On NVIDIA driver 610.88 "Local Memory Size" carries bit 36 as a flag: the spill size in
  bytes is the value minus 2^36. Without the extension (another host) nothing changes.
- `CAELIX_UPLOAD_PATH`: `auto` (default), `bar` or `bounce`; the record upload path that
  `caelix_scene_create` uses (see "Record upload path"). `bar` fails the creation with
  `CAELIX_ERROR_OUT_OF_MEMORY` when the ring cannot be allocated in device-local, host-visible memory.
- `CAELIX_LIB_DIR`: directory that contains `caelix_renderer.lib` and
  `caelix_renderer.dll`. Default: `<repo>/build/bin/Release`. The Rust host
  links the Release build only.
- `LIBCLANG_PATH`: directory that contains `libclang.dll`, used by bindgen.
  `host-rs/.cargo/config.toml` sets it to the 64-bit Visual Studio 2022
  Community LLVM directory (`VC/Tools/Llvm/x64/bin`); set your own value if your
  installation is different. Do not use `VC/Tools/Llvm/bin`: its
  `libclang.dll` is 32-bit.
